# 后端与内存

## 1. 设备枚举与选择

```cpp
for (size_t i = 0; i < device_count(); ++i) {
    Device* d = device_get(i);
    std::printf("%zu: %s (%s)\n", i, d->props().name.c_str(), d->props().description.c_str());
}

Device* cpu = device_cpu();                              // CPU 参考后端
Device* gpu = device_by_type(DeviceType::GPU);           // 独显
if (gpu == nullptr) gpu = device_by_type(DeviceType::IGPU);  // 核显
if (gpu == nullptr) gpu = cpu;                           // 回退
```

`DeviceProps` 提供 `name`、`description`、`type`、`memory_free`、`memory_total`、`unified_memory`。

- CPU 后端：数据在主机内存，通用步长路径。
- Vulkan 后端：同一份代码跨设备运行；找不到 SDK 时在构建期自动关闭；运行期找不到设备时 `vulkan_device()` 返回空指针，注册表跳过，不中止。
- `Device::default_buffer_type()` 返回默认缓冲类型；`Device::alloc_buffer(size)` 可直接分配缓冲。

## 2. 能力查询

不同后端支持的算子与类型范围不同。`Device::supports_op(tensor)` 是唯一门控，`graph_first_unsupported` 用于整图预检：

```cpp
const Tensor* bad = graph_first_unsupported(g, dev);
if (bad != nullptr) {
    // bad 是第一个当前设备不支持的节点
    // 处理方式：换设备、改用等价算子组合，或提前报错
}
```

不支持的节点在执行前明确中止（Vulkan 分派前校验、CPU kernel 断言），不会静默跳过或错算。详细支持矩阵见《算子参考》与《功能与限制》。

## 3. 张量数据分配

`ContextParams.no_alloc` 默认 `true`：`new_tensor_*` 只创建元数据，数据由后端 buffer 统一分配。

### 3.1 整上下文分配

```cpp
Buffer* buf = buffer_alloc_ctx_tensors(ctx, dev->default_buffer_type());
```

- 为上下文中所有待分配张量一次性分配，并设置 `t->buffer` / `t->data`。
- 视图在此阶段解析 `data` 指针。
- 跳过已有 `data` 的张量（便于与自行分配的状态缓冲共存）。
- 分配失败会打印“需要 X / 上限或可用 Y”并中止。

### 3.2 图级生命周期复用

训练图（前向 + 反向）建议使用图级分配：生命周期不重叠的中间量复用同一段缓冲，降低峰值。

```cpp
graph_build_forward_expand(ctx, g, loss);
graph_build_backward_expand(g);
Buffer* buf = buffer_alloc_graph_tensors(g, dev->default_buffer_type());
```

- 要求图覆盖上下文中全部待分配的非视图张量（前向 + 反向训练图天然满足），否则中止。
- **compute 后读取契约**：一次 `graph_compute` 之后，只有参数、损失、图输出，以及显式标记 `TENSOR_FLAG_OUTPUT` 的张量/视图可安全读取。其余中间量与视图可能已被复用覆盖。

```cpp
// 需要在 compute 之后读取的中间量/视图，在构建图之前标记
y_hat->flags |= TENSOR_FLAG_OUTPUT;
```

- 若需要逐个检查所有中间量，改用 `buffer_alloc_ctx_tensors`（不复用，语义简单）。

### 3.3 释放

```cpp
buffer_free(buf);
```

释放后，归属该 buffer 的张量与视图的 `data` / `buffer` 指针会被清空；再次 `buffer_alloc_*` 会重新分配。不要跨 `buffer_free` 使用张量数据。

### 3.4 自行分配缓冲

```cpp
Buffer* b = dev->alloc_buffer(bytes);
tensor_set(t, data, 0, bytes);   // 或通过后端接口绑定
// ...
buffer_free(b);
```

## 4. 内存核算

```cpp
ContextMemoryStats cm = context_memory_stats(ctx);
// cm.tensor_bytes / cm.persistent_bytes / cm.view_count

AllocStats as = backend_alloc_stats();
// as.current_bytes / as.peak_bytes / as.n_allocations
backend_alloc_stats_reset();   // 重置基线（之后释放旧 buffer 不再扣减）
```

- `persistent_bytes` 为保守口径（仍把视图源计入持久）。
- `AllocStats` 只统计核心路径（`buffer_alloc_ctx_tensors` / 图级分配 + 优化器状态块），`buffer_free` 统一扣减。

## 5. 反复建图与回收

每 epoch / 变长样本反复建图时，旧图的中间量会留在 Context 中。用 `context_release_graph_tensors` 回收：

```cpp
Graph* g = graph_new(ctx);
for (每个 batch / epoch) {
    graph_clear(g);
    graph_build_forward_expand(ctx, g, loss);
    graph_build_backward_expand(g);
    Buffer* buf = buffer_alloc_graph_tensors(g, dev->default_buffer_type());
    // ... graph_reset + graph_compute + optim_step ...
    buffer_free(buf);                            // 先释放数据字节
    context_release_graph_tensors(ctx, g);       // 再回收图中间量
}
```

- 回收对象：图内“非持久/非钉住、非视图、有节点读取”的中间量。参数、损失、梯度累加器、输入叶子、图输出以及钉住的视图根保留。
- 张量元数据（约 300 B/张量，含视图）不回收；需要彻底回收请重建 Context。
- 顺序必须是 `buffer_free → context_release_graph_tensors`。
- 变长样本的新输入叶子不会被回收；建议用固定最大尺寸的输入缓冲 + 视图/拷贝。

## 6. Vulkan 运行细节

### 6.1 内存放置

计算缓冲默认 **host-visible + coherent（系统内存，GPU 经 PCIe 访问）**，`Buffer::base()` 返回真实主机指针。这是因为库的优化器与梯度清零是主机标量实现。相关环境变量：

| 变量 | 作用 | 默认 |
|---|---|---|
| `TRC_VK_DEVICE_LOCAL=1` | 计算缓冲优先 device-local（显存）；失败回退 host-visible | 关闭 |
| `TRC_VK_HOST_MEMORY=1` | 显式强制 host-visible | 关闭 |

### 6.2 设备与校验

| 变量 | 作用 |
|---|---|
| `TRC_VK_DEVICE` | 选择物理设备：整数为序号，否则按设备名子串匹配 |
| `TRC_VK_VALIDATE=1` | 启用 Vulkan 校验层；消息以 `[traincpp][...][vulkan]` 打印 |

### 6.3 提交与 device-lost

整图默认**单个命令缓冲一次提交**。长提交可用 `TRC_VK_CHUNK_NODES=n` 每 n 个节点提交一次，以降低 Windows TDR 暴露（数值不变）。

提交或等待失败会打印 `VkResult` 名称与数值、本次 dispatch 数与进程存活缓冲。`VK_ERROR_DEVICE_LOST` 视为进程内不可恢复，必须终止训练。详见《问题排查》。

### 6.4 设备上限

Vulkan 后端显式校验 `maxBufferSize`、`maxMemoryAllocationSize`、`maxStorageBufferRange`，超限即中止并打印“需要/上限”。单上下文峰值建议控制在设备单缓冲上限以内，或分块 / 多上下文。

### 6.5 索引越界

索引类算子（`get_rows` / `get_rows_back` / `set_rows`）越界时，Vulkan 经设备端错误缓冲在 `graph_compute` 结束后中止，CPU 立即中止；两端语义一致。详见《问题排查》。

## 7. 内存规划建议

- 训练使用 `no_alloc=true` + `buffer_alloc_graph_tensors`，降低峰值。
- 需要逐中间量读取时使用 `buffer_alloc_ctx_tensors`。
- 长循环配合 `context_release_graph_tensors`。
- 变长样本使用固定最大尺寸输入缓冲 + 视图/拷贝，避免每步新建叶子。
