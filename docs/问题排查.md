# 问题排查

本文说明库的报错与日志体系、如何判断错误来源，以及常见中止原因与定位方法。

## 1. 日志与消息体系

库把所有日志与错误输出到 **stderr**，每条立即刷新。消息前缀固定为 `[traincpp][级别]`。

| 前缀 | 含义 | 行为 |
|---|---|---|
| `[traincpp][FATAL]` | API 误用或内部不变量被破坏 | 打印后 `abort`，进程立即终止 |
| `[traincpp][ERROR]` | 可恢复错误（如文件损坏、类型不符） | 打印，相关 API 返回 `nullptr` / `false` |
| `[traincpp][WARN]` | 可恢复的降级或环境问题 | 打印，继续执行 |
| `[traincpp][INFO]` | 状态提示（设备就绪、校验通过等） | 打印 |
| `[traincpp][DEBUG]` | 调试信息（Vulkan 校验层低严重度消息） | 打印 |

`FATAL` 的输出格式：

```
[traincpp][FATAL] <文件>:<行号>: <消息>
```

`<文件>:<行号>` 直接指向库内中止点。进程退出码由 `std::abort()` 决定（Windows 下通常为异常终止，非自定义退出码）。

日志级别没有开关或过滤机制，也没有可替换的日志回调。

## 2. 如何判断错误来源

| 日志形态 | 来源 | 处理方向 |
|---|---|---|
| `[traincpp][FATAL] ...` 且无 `VkResult=` | 库侧不变量 / API 误用 | 检查调用顺序、张量形状/类型、模型规模、图构建 |
| `[traincpp][FATAL] ... VkResult=<名称>/<数值> ...` | Vulkan API / 驱动返回了非成功结果 | 按第 3 节分析该 `VkResult` |
| `[traincpp][ERROR] ...` | 可恢复错误（IO / 校验 / 类型） | 检查返回值，修正输入或文件 |
| `[traincpp][WARN] ...` | 环境降级（如回退 host-visible、Vulkan 初始化失败跳过） | 视需要处理；不影响正确性时可不处理 |
| `[traincpp][ERROR] [vulkan] ...` | Vulkan 校验层报告（需 `TRC_VK_VALIDATE=1`） | 通常指向库侧用法问题 |

判断要点：

- **出现 `VkResult=`** 表示是 Vulkan API 或驱动返回了错误码；这是与“库主动中止”最明确的区分标志。
- **没有 `VkResult=`** 的 `FATAL` 是库自己的断言，`<文件>:<行号>` 指出位置。
- `VK_ERROR_DEVICE_LOST` 是唯一被显式标注为**进程内不可恢复**的情况。

## 3. Vulkan 故障诊断

### 3.1 通用 VkResult 失败

执行 Vulkan API 失败时，库打印：

```
VkResult=<名称>/<数值>：<原始消息>
```

`<名称>` 便于直接查表；`<数值>` 是 `VkResult` 的整数值。例如 `VkResult=VK_ERROR_OUT_OF_DEVICE_MEMORY/-2`。

VkResult 的权威定义见 Vulkan 头文件 `vulkan/vulkan_core.h` 的 `VkResult` 枚举与 Khronos Vulkan 规范的 Return Codes 章节。常用值：

| 名称 | 数值 | 含义 |
|---|---|---|
| `VK_SUCCESS` | 0 | 成功 |
| `VK_ERROR_OUT_OF_HOST_MEMORY` | -1 | 主机内存不足 |
| `VK_ERROR_OUT_OF_DEVICE_MEMORY` | -2 | 设备内存不足（规模过大） |
| `VK_ERROR_INITIALIZATION_FAILED` | -3 | 初始化失败（驱动/环境） |
| `VK_ERROR_DEVICE_LOST` | -4 | 设备丢失（不可恢复） |
| `VK_ERROR_MEMORY_MAP_FAILED` | -5 | 映射失败 |

### 3.2 提交 / 等待失败

`vkQueueSubmit` / `vkWaitForFences` 失败会附带本次提交的上下文：

```
VkResult=<名称>/<数值>：Vulkan 后端 <动作> 失败；本次提交 <N> 个 dispatch，进程存活缓冲 <M> MiB
```

其中 `<N>` 是本次图计算的 dispatch 数，`<M>` 是当前存活的 Vulkan 缓冲字节数（用于判断是否规模过大）。

### 3.3 设备丢失（DEVICE_LOST）

```
VkResult=VK_ERROR_DEVICE_LOST/-4：Vulkan 后端 <动作> 设备丢失（Windows TDR/驱动重置/硬件挂起）。本次提交 <N> 个 dispatch，进程存活缓冲 <M> MiB；device-lost 后该设备与全部资源失效，进程内无法恢复，训练必须终止。建议：...
```

语义：设备与全部资源失效，**不可恢复**，必须终止训练。可尝试的缓解：

1. 减小单次提交规模（`TRC_VK_CHUNK_NODES`）。
2. 检查 / 放宽 Windows TdrDelay 与驱动，或改用 CPU 后端 / 另一块 GPU。
3. 复现时带 `TRC_VK_VALIDATE=1`，并附上完整消息。

### 3.4 索引越界

索引类算子（`get_rows` / `get_rows_back` / `set_rows`）越界会中止：

- CPU：kernel 内立即 `[FATAL] get_rows: 索引越界 <值>（词表大小 <n>）`。
- Vulkan：设备端写入错误缓冲，`graph_compute` 提交并等待完成后检查并 `[FATAL] Vulkan 后端：<op> 索引越界（索引值 <值>，词表/目标行数见张量形状）——CPU 后端同样中止，请检查索引数据范围`。

两端语义一致（中止，不静默）。请检查索引数据范围。`set_rows` 的**重复**索引是未定义行为（写入非原子），需保证索引唯一。

## 4. 常见中止原因速查

### 4.1 图与自动求导

| 消息要点 | 触发条件 |
|---|---|
| `没有可训练参数：请先调用 tensor_set_param` | 未标记任何参数 |
| `没有损失：请先调用 tensor_set_loss` | 未标记损失 |
| `前向图为空` | 图为空 |
| `同一 Graph 已构建过反向（重复展开会静默双倍梯度）` | 重复 `graph_build_backward_expand` |
| `检测到多图共享张量 ... 禁止多图共享参数/梯度路径中间量` | 参数或梯度路径中间量属于另一张已构建反向的图 |
| `算子 <op> 的反向尚未实现` | 使用了无反向的算子 |
| `tensor_set_param: 只能标记无输入的叶子张量（当前 op=<op>）` | 对非叶子调用 `tensor_set_param` |
| `tensor_set_loss: 损失必须是 f32` / `损失必须是标量` | 损失类型/形状不符 |

### 4.2 内存分配

| 消息要点 | 触发条件 |
|---|---|
| `buffer_alloc_ctx_tensors: buffer 分配失败：需要 X 字节（... MiB），设备 '<dev>' 可用 Y 字节 / 总 Z 字节` | 上下文分配超出设备可用内存 |
| `图未覆盖张量 <t>（op=<op>）；请先把该张量加入图，或改用 buffer_alloc_ctx_tensors` | 图级分配时张量不在图中 |
| `张量 <t> 的生命周期非法（生产 X >= 最后使用 Y）` | 图非拓扑序 / 生命周期计算异常 |
| `张量请求 ... 超过设备 maxBufferSize / maxMemoryAllocationSize / maxStorageBufferRange 上限` | 单缓冲 / 单次分配 / descriptor range 超硬上限 |
| `优化器状态分配失败：需要 X 字节 ...` | 优化器状态超出可用内存 |
| `context_new/context_alloc: ... 需要 X 字节 ...` | Context arena 或外部内存不足 |

处理方向：减小 batch / 序列长度，分块，或换设备 / 多 Context。

### 4.3 类型与布局

| 消息要点 | 触发条件 |
|---|---|
| `CPU 后端不支持算子 <op>` | CPU 无该 kernel |
| `Vulkan 后端不支持算子 <op>（类型/布局不满足支持声明）` | 该后端不支持该类型/布局组合 |
| `Vulkan 后端尚未实现算子 <op>` | 该算子无 Vulkan 实现 |
| `Vulkan cast 仅支持 F32↔F16` | `cast` 的类型组合超出 Vulkan 范围 |
| `Vulkan set_rows 值仅支持 F32` / `索引仅支持 I32` | 类型超出 Vulkan 范围 |
| `Vulkan 后端仅支持 F32/I32/F16 类型` | 绑定了其他类型 |
| `new_tensor: 数据类型 <t> 不支持分配` | 试图分配量化类型 |
| `数据类型 <n> 尚未实现` | 使用了未登记的类型 |
| `视图暂不支持量化类型` | 对量化张量建视图 |

处理方向：用 `graph_first_unsupported(graph, dev)` 在训练前确认；换设备、改用等价的算子组合，或改为 F32。

### 4.4 算子构造约束

构造算子时若形状/类型不满足会立即中止，消息直接给出原因，例如：

- `mul_mat: 内维不一致`、批量维不整除
- `add: 形状不满足广播`、`add1: 第二个输入必须是标量`
- `get_rows: 索引类型必须是 I32`、`表类型一期仅支持 f32/f16`
- `soft_max: 输入必须连续`、`mask.ne[0] 必须等于输入的 ne[0]`
- `repeat: a 无法重复到 target 的形状`
- `pad_ext: 补齐量必须非负`、reflect 要求每侧小于对应维长度
- `conv_transpose_1d: 一期仅支持 p0==0` / `d0==1`
- `concat: 第 <d> 维形状不一致`

### 4.5 GGUF

| 消息要点 | 说明 |
|---|---|
| `GGUF: 魔数不正确（不是 GGUF 文件）` | 文件不是 GGUF |
| `GGUF: 不支持的版本 N（仅支持 v2/v3）` | 版本越界 |
| `GGUF: 读取端暂不支持类型 <t>` | 量化类型无实现 |
| `GGUF: 张量 <t> 类型不匹配（目标 <a>，文件 <b>），目标须为 F32 或同类型` | `gguf_load_tensor` 目标类型不符 |
| `GGUF: 张量 <t> 必须连续` / `元素数不匹配` | 目标张量不符 |
| `GGUF: 仅支持小端主机` | 大端平台 |

### 4.6 checkpoint

| 消息要点 | 说明 |
|---|---|
| `不是 checkpoint 文件（general.architecture 不符）` | 非 checkpoint |
| `schema 版本不支持` | 版本越界 |
| `优化器分组/参数数量不匹配`、`优化器类型不匹配`、`优化器超参不匹配` | 与当前优化器不一致 |
| `参数名列表不匹配`、`状态张量名列表不匹配` | 模型结构或命名不一致 |
| `优化器状态未分配（请先调用 optim_alloc_state）` | 载入前未分配状态 |
| `调度器 epoch 大于存档，无法回退` | 调度器只能前进 |

### 4.7 Vulkan 启动与运行

- 可恢复（`WARN`，后端被跳过，不中止）：`vkCreateInstance 失败`、`未找到物理设备`、`没有满足条件的计算设备（TRC_VK_DEVICE=...）`、`vkCreateDevice 失败`、错误标志缓冲创建失败。
- 直接中止：绑定数超限、dispatch 网格超上限、descriptor set 分配失败、找不到 shader、张量未绑定 buffer / 超出缓冲范围、张量未按类型宽度对齐。
- 显存不足：先 `WARN` 打印需要量与设备总显存，再由核心层统一“需要 / 上限或可用”中止。

## 5. 环境变量

### 5.1 运行时（库）

| 变量 | 作用 | 默认 |
|---|---|---|
| `TRC_VK_DEVICE` | 选择 Vulkan 物理设备（整数序号或设备名子串） | 自动评分选优 |
| `TRC_VK_VALIDATE=1` | 启用 Vulkan 校验层（消息以 `[traincpp][...][vulkan]` 打印） | 关闭 |
| `TRC_VK_DEVICE_LOCAL=1` | 计算缓冲优先显存（失败回退 host-visible） | 关闭 |
| `TRC_VK_HOST_MEMORY=1` | 显式强制 host-visible | 关闭 |
| `TRC_VK_CHUNK_NODES=n` | 每 n 个节点分块提交（降低 TDR 暴露） | 0（整图单次） |

### 5.2 测试与工具

| 变量 | 作用 |
|---|---|
| `TRC_TEST_DEVICE=cpu|vulkan` | 测试选择设备 |
| `TRC_STRESS_SCALE=small|full` | 压力用例档位 |

### 5.3 测试钩子（一般无需使用）

以下变量用于构造边界/死亡测试，正常使用不应设置：

`TRC_VK_FORCE_SUBMIT_RESULT`（伪造提交结果）、`TRC_VK_MAX_GROUPS`、`TRC_VK_MAX_STORAGE_RANGE`。

## 6. 复现与信息收集

1. 保留完整 stderr 输出；`[traincpp][FATAL]` 行含 `<文件>:<行号>` 与具体消息。
2. 若含 `VkResult=`，记录名称与数值，并按第 3 节查表。
3. GPU 相关问题带上 `TRC_VK_VALIDATE=1`、`TRC_VK_DEVICE_LOCAL` / `TRC_VK_HOST_MEMORY` 的设置，以及 `TRC_VK_CHUNK_NODES` 的取值。
4. 记录设备信息（`device_count()` / `DeviceProps`）与模型规模（batch、序列长度、单张量元素数）。
