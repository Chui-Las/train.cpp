# 示例程序

`examples/` 下包含最小示例与可操作的演示程序。构建方式见《构建与集成》；开启 `TRC_BUILD_EXAMPLES`（默认）后，可执行文件输出到构建目录的 `bin/`（预设路径为 `out/build/release/bin/`）。

## 1. 示例一览

| 程序 | 用途 | 需要数据 | 可用 GPU |
|---|---|---|---|
| `example_basic` | 最小前向计算 | 否 | 否 |
| `example_train` | MLP 训练 + checkpoint + GGUF 导出 | 否（内置合成） | 可选 |
| `demo_image_train` | 训练一个小 CNN 做图像分类并导出模型 | 可用内置合成或自备目录 | 是 |
| `demo_image_classify` | 加载模型对图片分类 | 需训练导出的模型 | 是 |

## 2. example_basic —— 最小前向

计算 `y = sigmoid(a * a)`，演示 Context / Tensor / Graph 与 `graph_compute` 的最短路径。

```sh
out/build/release/bin/example_basic
```

## 3. example_train —— 完整训练链路

训练一个 `Linear(4→8) → ReLU → Linear(8→1)` 的 MLP 拟合合成数据，随后保存 checkpoint、探测、在新会话中恢复并校验，并导出 GGUF 后回读比对。演示完整的公共 API 用法。

```sh
out/build/release/bin/example_train
```

产物写入系统临时目录（`.ckpt.gguf` 与 `.gguf`）。

## 4. demo_image_train —— 图像分类训练

训练一个小型 CNN 图像分类器并导出 GGUF 模型。

网络（刻意不使用池化，以保证 CPU / Vulkan 均可训练）：

```
Conv2d(1→8,  k3,s1,p1) + ReLU
Conv2d(8→16, k3,s2,p1) + ReLU
Conv2d(16→16,k3,s2,p1) + ReLU
reshape → Linear(F→64) + ReLU → Linear(64→K)
交叉熵损失（目标为 one-hot）
```

### 4.1 开箱即用（内置合成数据）

不提供数据时，程序会生成 3 类合成图案（`horizontal` 横条纹 / `vertical` 竖条纹 / `checker` 棋盘格）进行训练：

```sh
out/build/release/bin/demo_image_train --synthetic --epochs 15 --export model.gguf
out/build/release/bin/demo_image_train --device gpu --epochs 15 --export model.gguf   # 用 Vulkan
```

### 4.2 生成磁盘数据（可选）

把合成数据写成 PGM 文件，便于查看格式或手工修改：

```sh
out/build/release/bin/demo_image_train gen-data --out demo_data --classes 3 --per-class 60 --size 24
```

### 4.3 使用自己的图片

数据目录按类别分文件夹：

```
<数据目录>/
  <类别名 A>/*.bmp|.pgm|.ppm
  <类别名 B>/*.bmp|.pgm|.ppm
  ...
```

```sh
out/build/release/bin/demo_image_train --data <数据目录> --epochs 20 --batch 16 \
    --device gpu --size 24 --export model.gguf
```

- 图片自动转灰度并缩放到 `--size`（默认 24，需为 4 的倍数）。
- 类别顺序为子目录名的字典序；每类建议 30 张以上。
- 支持的图片格式：BMP（24/32 位未压缩）、PGM（P2/P5）、PPM（P3/P6）。

### 4.4 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--data <目录>` | 空 | 使用磁盘数据；为空则用内置合成数据 |
| `--synthetic` | 未指定数据时启用 | 强制使用内置合成数据 |
| `--classes` | 3 | 合成数据类别数（最多 3 种图案） |
| `--per-class` | 60 | 合成数据每类张数 |
| `--size` | 24 | 输入边长（4 的倍数） |
| `--epochs` | 20 | 训练轮数 |
| `--batch` | 16 | 批量大小 |
| `--device` | cpu | `cpu` 或 `gpu`（Vulkan；无设备时回退 CPU） |
| `--export` | demo_model.gguf | 模型输出路径 |

### 4.5 输出

逐 epoch 打印训练损失与评估损失/准确率，最后导出并自检 GGUF：

```
epoch   1/15  train_loss 1.1022  eval_loss 1.0397  eval_acc 55.4%
...
epoch  15/15  train_loss 0.0001  eval_loss 0.0000  eval_acc 100.0%
已导出模型: model.gguf
```

## 5. demo_image_classify —— 加载模型并分类

```sh
out/build/release/bin/demo_image_classify --model model.gguf <图片> [<图片> ...] [--device cpu|gpu]
```

读取模型元数据（输入尺寸、类别名），重建同结构网络并载入权重，对每张图片输出预测类别与各类概率：

```
<图片路径>
  预测: vertical  (100.0%)
  概率: checker=0.000 horizontal=0.000 vertical=1.000
```

## 6. 把自己的图片转成支持的格式

演示程序只解码 BMP / PGM / PPM（零第三方依赖）。若图片是 PNG/JPG：

- Windows：用“画图”打开后“另存为” 24 位 BMP。
- 命令行（若已安装 ImageMagick）：`magick input.png -colorspace Gray output.pgm`。
- Python（若已安装 Pillow）：`python -c "from PIL import Image; Image.open('in.png').convert('L').save('out.pgm')"`。

## 7. 说明与边界

- 演示用于展示“能训练、可用 GPU、是 C++”的完整闭环，网络与数据规模都很小，不代表性能。
- 仅支持上述三种图片格式；其余格式需先转换。
- 固定输入尺寸与批量；数据量不能被批量整除时，训练会丢弃最后不足一批的样本。
- `--device gpu` 需要 Vulkan 设备；找不到时回退 CPU 并提示。
- 首次枚举设备时，若存在 Vulkan 设备，库会打印少量 `[traincpp][INFO]` 初始化信息（属正常行为）。
