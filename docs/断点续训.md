# 断点续训

checkpoint 复用 GGUF 容器（`general.architecture = "traincpp.checkpoint"`），保存参数、优化器状态与超参、每参数状态步数，以及可选的随机数与调度器 epoch。写端恒为 schema v2，读端兼容 v1 / v2。

## 1. 保存内容

- 全部参数张量（名字取 `Tensor::name`，必须非空且唯一；优化器要求 F32、连续、非视图）。
- 优化器状态张量：SGD `<param>.momentum`；AdamW `<param>.m` / `<param>.v`。
- 元数据（按优化器分区）：分区名、类型、分组、全局 step、每组 lr 与非 lr 超参、参数名与状态名列表、每参数状态步数；可选每分区调度器 epoch。
- 可选：随机数状态（多优化器共享一份）。

## 2. 保存

```cpp
checkpoint_save("train.ckpt.gguf", CheckpointItems{a.opt, &a.rng, sched}, "my.model");
checkpoint_verify("train.ckpt.gguf", CheckpointItems{a.opt, &a.rng, sched});   // 可选自检
```

前提：参数与状态张量的数据必须已分配（参数经 `buffer_alloc_*`；状态经 `optim_alloc_state` 或已 step 过）。`step_count > 0` 但状态未分配时报错，避免写出无法续训的检查点。

## 3. 加载（断点续训）

在**新进程**中恢复：

```cpp
// 1) 重建同结构模型（层结构、参数名必须一致）
// 2) 构建前向/反向图 -> buffer_alloc_ctx_tensors
// 3) 创建同类型、同超参的优化器与调度器
// 4) 分配优化器状态（文件中含状态时需要）
optim_alloc_state(opt);
// 5) 载入
checkpoint_load("train.ckpt.gguf", CheckpointItems{opt, &rng, sched});
// 6) 继续训练循环
```

顺序上，`checkpoint_load` 会校验 arch / 版本 / 分区 / 类型 / 分组 / 参数名与状态名，然后载入张量、恢复 step、恢复每组 lr，并按分区回放调度器到存档 epoch。

## 4. 多优化器

双网络（如 GAN 的 G / D）各自一个优化器，保存到同一文件：

```cpp
CheckpointOptimizer parts[2] = {
    {"G", opt_g, sched_g},
    {"D", opt_d, sched_d},
};
CheckpointItems items{};
items.rng             = &rng;    // 共享一份 RNG
items.optimizers      = parts;
items.optimizer_count = 2;
checkpoint_save("gan.ckpt.gguf", items, "gan");
checkpoint_verify("gan.ckpt.gguf", items);

// 载入：新进程重建两个优化器（各自 optim_alloc_state）后按分区名匹配（顺序无关）
checkpoint_load("gan.ckpt.gguf", items);
```

约定：

- 分区名必填、非空且唯一；跨分区的参数 / 状态张量名不得重复（GGUF 要求全局唯一）。
- 每个分区可带自己的调度器；载入时逐分区回放到存档 epoch。
- 单优化器可用 `CheckpointItems{opt, &rng, sched}`（v1 / v2 均可载入；旧字段加载 v2 文件时要求文件只有一个分区）。

## 5. 探测

```cpp
CheckpointInfo info;
checkpoint_probe("train.ckpt.gguf", &info);
// info.version / step / param_count / group_count / optimizer_type / model_arch
// info.has_rng / has_scheduler / scheduler_epoch / optimizer_count
```

`probe` 只读元数据，不加载张量。字段取第 0 个分区（v1 语义）。

## 6. 自检

```cpp
checkpoint_verify("train.ckpt.gguf", items);
```

只读重新打开文件，与当前优化器逐项比对：参数 / 状态张量数据（逐元素）、step、每组 lr、超参、RNG 状态、调度器 epoch（多优化器逐分区）。全部一致返回 `true` 并打印摘要。

## 7. 严格匹配与注意事项

- 载入是**严格匹配**：参数名 / 数量、优化器类型、非 lr 超参、状态名等不一致会返回 `false` 并打印原因。
- 状态张量需已分配（`optim_alloc_state` 或已 step 过）。
- 调度器 epoch 只能前进；载入时用 `lr_scheduler_step` 回放。
- 单个优化器内不支持组间混合类型（SGD + AdamW）；不同分区之间可以混用。
- 续训与不中断训练的参数轨迹逐位一致（含 AdamW 的 bias correction）。

## 8. 常见错误

- `不是 checkpoint 文件（general.architecture 不符）`
- `schema 版本不支持`
- `优化器分区数量不匹配` / `找不到优化器分区`
- `优化器分组/参数数量不匹配`、`优化器类型不匹配`、`优化器超参不匹配`
- `参数名列表不匹配`、`状态张量名列表不匹配`
- `优化器状态未分配（请先调用 optim_alloc_state）`
- `调度器 epoch 大于存档，无法回退`
- `参数数据不一致` / `状态数据不一致`（自检）

完整消息见《问题排查》。
