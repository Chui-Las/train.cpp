# 测试

本文档说明测试框架、如何运行、每个测试程序做什么，以及测试覆盖的边界。

## 1. 测试框架

自研轻量框架，不引入第三方依赖。

- 每个测试文件用 `TRC_TEST(name)` 注册用例（静态自注册），由 `tests/test_main.cpp` 统一顺序运行。
- 断言宏：`TRC_EXPECT(cond)`、`TRC_EXPECT_EQ(a, b)`、`TRC_EXPECT_NEAR(a, b, eps)`。
- 单个断言失败不会中断当前进程：失败信息写入 stderr 并计入该用例，跑完全部用例后汇总。退出码：`0` = 全部通过，`1` = 至少一个用例失败。
- 用例内可直接 `return` 表示“跳过”，跳过计为通过。

文件构成：

| 文件 | 作用 |
|---|---|
| `tests/test_util.h` | 框架：`TRC_TEST` / 断言 / 设备选择 / 整图预检辅助 |
| `tests/test_main.cpp` | 用例注册表与 `main()` |
| `tests/npy.h` | 最小 `.npy` 读取器（仅 C 序、小端） |
| `tests/expect_abort.cmake` | 死亡测试包装：期望进程非 0 退出 |

## 2. 运行方式

```sh
# 构建后
ctest --test-dir build --output-on-failure

# 直接运行某个测试程序
build/bin/test_ops

# 指定设备（默认为 cpu）
TRC_TEST_DEVICE=vulkan  build/bin/test_grad
```

- 测试注册在 `tests/CMakeLists.txt`，受 CMake 选项 `TRC_BUILD_TESTS` 控制。
- `TRC_VULKAN=ON` 时共 **47** 个 CTest 用例；`TRC_VULKAN=OFF` 时共 **23** 个（Vulkan 相关用例不注册）。
- 每个功能测试程序是可执行文件；死亡测试由 `expect_abort.cmake` 包装运行。

## 3. 环境变量

| 变量 | 作用 | 取值 |
|---|---|---|
| `TRC_TEST_DEVICE` | 测试使用的设备 | `cpu`（默认）/ `vulkan` |
| `TRC_STRESS_SCALE` | 压力测试档位 | `small`（默认）/ `full` |
| `TRC_GOLDEN_DIR` | 黄金数据目录 | 编译期宏，由 CMake 注入为 `<源码>/tests/golden` |

Vulkan 相关测试还使用若干环境变量（`TRC_VK_CHUNK_NODES`、`TRC_VK_HOST_MEMORY`、`TRC_VK_DEVICE_LOCAL`、`TRC_VK_MAX_GROUPS`、`TRC_VK_MAX_STORAGE_RANGE`、`TRC_VK_FORCE_SUBMIT_RESULT`），其中后三个为测试钩子。详见《问题排查》§5。

设备选择逻辑：`TRC_TEST_DEVICE=vulkan` 时先找独显再找核显；无可用 Vulkan 设备（或构建时 `TRC_VULKAN=OFF`）时用例打印“跳过”并返回，进程仍退出 `0`，CTest 记为 **PASSED**。

## 5. 功能与单元测试

### 5.1 test_core

core 基础设施：

- 类型表（`type_size` / `type_blck_size` / `type_row_size` / `type_is_quantized` / `type_name`）。
- 张量形状与步长（`ne` / `nb`、`nelements` / `nrows` / `nbytes` / `n_dims` / `is_contiguous`）。
- 上下文 arena 追加、张量命名与 `tensor_dup_meta`。
- 图展开拓扑序、叶子数、去重，以及 `graph_first_unsupported`。

边界：固定 CPU，不读 `TRC_TEST_DEVICE`；只验证类型/形状元数据与图结构，不执行数值 kernel，不做内存分配生命周期验证。

### 5.2 test_ops

CPU 参考后端的算子数值与形状（61 个用例）：逐元素二元/一元/激活、`mul_mat`（含 batch 广播）、视图/reshape/permute/concat/repeat/pad（含 reflect）、归约与归一化（含 `*_back`）、`soft_max`、索引、`cast`（含 F16 次正规数与往返）、卷积与池化、转置卷积、`acc`、交叉熵，以及 `supports_op` 的类型约束声明。

边界：固定 CPU；绝大多数为 F32；张量规模极小；部分反向用解析小例（系统梯度验证在 `test_grad`）；不验证大规模 dispatch 与内存复用（在 `test_alloc` / `test_stress`）；`pool_2d_back` 仅 CPU；不覆盖 `set_rows` 重复索引等未定义行为。

### 5.3 test_alloc

分配 / 释放生命周期与内存治理（15 个用例）：

- `buffer_free` 后张量与视图的 `data` / `buffer` 失效，重分配后正确重绑定。
- 内存核算 API（`context_memory_stats` / `backend_alloc_stats`）。
- 图级复用：`alloc_graph_reuse`（峰值下降）、`alloc_graph_training_equiv`（与整上下文分配逐位一致）、`alloc_stats_no_growth_in_training`（训练步零核心分配）。
- 反复建图与回收：`alloc_release_rebuild`（100 轮分配字节恒定）。
- 视图根 / 多后继 / 钉住：`alloc_graph_view_root_reuse`、`alloc_graph_view_output_pin`、`alloc_graph_external_view_pin`、`alloc_graph_multi_reader_reuse`、`alloc_graph_view_multi_reader_equiv`。

边界：规模小（最多约 32 KiB、100 轮循环），不测大张量（在 `test_stress`）；只统计核心路径 Buffer；不穷举所有内存所有权组合。

### 5.4 test_grad

用中心有限差分（gradcheck）与解析断言验证 autograd（42 个用例）：二元/一元/激活、归约/归一化、`mul_mat`（含 batch）、卷积/池化/转置卷积、`pad`（零与 reflect）、`scale_bias`、`soft_max`、交叉熵、`repeat` / `reshape` / `transpose` / `permute` / `view` / `concat` / `get_rows`、梯度累加与复用、端到端 MLP（SGD）。

边界：差分参数固定（`eps=1e-2`、相对容差约 `5e-3`），只对小规模 F32 有效；不可导点用解析断言或避开；只 F32；`pool_2d_back` 在 Vulkan 无实现，相关用例在 `grad_vulkan` 下被预检跳过，故 Vulkan 未覆盖池化反向。

### 5.5 test_nn

nn 层系统（14 个用例）：黄金对拍（Linear / Embedding / Conv1d 含分组 / Conv2d / ConvTranspose1d / LayerNorm / RmsNorm / GroupNorm / WeightNorm）、gradcheck、ConvTranspose1d 批量路径（N=1 与 N>1 逐位一致）、尾部 1 维布局、`WeightNorm` 的 `sync_g` 与分组前向参照、初始化属性与自动标参、冻结/解冻、Dropout、端到端 MLP。

依赖 `tests/golden/nn_*`；缺失时黄金对拍跳过。固定 F32；`WeightNorm` 要求输出通道 > 1；Dropout 用统计比例断言；端到端为小型 MLP。

### 5.6 test_loss

`mse_loss` / `l1_loss` 黄金对拍、gradcheck、端到端线性回归（4 个用例）。依赖 `tests/golden/loss_*`；只 F32；不覆盖 reduction 变体。

### 5.7 test_optim

优化器与调度（10 个用例）：SGD（plain / momentum / nesterov / weight_decay）与 AdamW（含/不含 wd）黄金参数轨迹、调度器 lr 序列（step / exponential / cosine / warmup_cosine）、手算语义、`zero_grad` 与 `clip_grad_norm`、状态分配、参数分组与动态加组、梯度累积等价、端到端 MLP（AdamW + Cosine）。

依赖 `tests/golden/optim_*`；只 F32；累积等价用容差断言（非逐位）；不覆盖 Adam / RMSProp 等其它优化器。

### 5.8 test_gguf

GGUF 读写（10 个用例）：元数据全类型 round-trip、张量 round-trip（F32 / F16 / I32、F32→F16、对齐与偏移）、Q4_0 / Q4_1 / Q5_0 / Q5_1 / Q8_0 反量化、仅元数据加载、结构与损坏文件拒绝。

在系统临时目录读写文件；固定 CPU，不读 `TRC_TEST_DEVICE`；仅小端；不覆盖量化写出；不与 ggml 本体交叉（在 `tools/ggml_crosscheck`）。

### 5.9 test_checkpoint

checkpoint（8 个用例）：单优化器 round-trip、断点续训轨迹等价、SGD momentum 路径、多优化器 v2 round-trip 与续训逐位一致、schema v1 兼容读取、自检（篡改检测）、错误路径。

在系统临时目录读写文件；需要设备；固定小模型；续训等价用容差（多优化器 v2 为逐位）。

### 5.10 test_train_trace

重放 PyTorch 生成的固定小 MLP 多 epoch 训练轨迹，逐 epoch 比对参数与评估损失（`adamw`、`sgd_momentum` 两个 case）。依赖 `tests/golden/trace_*`；缺失即跳过；容差 `1e-5` 级。

### 5.11 test_gan

双图双优化器 GAN 协议（1 个用例）：冻结/解冻 + detach 输入，断言冻结参数无梯度、G 步不写 D 梯度、D 步不改 G，LSGAN 训练后 loss 下降且参数有限。

边界：网络很浅（Linear + ReLU），不覆盖卷积 / WeightNorm / 分组卷积 / reflect pad（在 `test_acceptance`）；收敛断言较宽松。

### 5.12 test_acceptance

端到端综合验收（1 个用例）：ConvTranspose1d 生成器（批内切片）+ 多周期 weight_norm / grouped Conv1d 判别器 + reflect pad + 双图双 AdamW / 双 Cosine + checkpoint v2 断点续训逐位一致 + GGUF 导出回读逐位。

在系统临时目录写文件；需要设备；为“功能贯通”而非规模 / 性能；多项能力耦合，单点失败定位需结合其它测试。

## 6. 对拍、一致性与压力

### 6.1 test_golden（前向黄金对拍）

逐算子把前向结果与 PyTorch 参考值对拍。读取 `tests/golden/cases.txt`（61 条）与对应 `.npy`，构建图并比较输出。容差：卷积 / cast 类 `atol=1e-3, rtol=2e-3`，其余 `atol=1e-4, rtol=1e-3`。黄金数据缺失、设备不可用、或图中含后端不支持算子时，相关用例跳过（分别统计并通过/跳过）。

### 6.2 test_grad_golden（反向黄金对拍）

按 `tests/golden/grad_cases.txt`（16 条）重放前向图并构建反向，比较损失与各参数梯度。容差 `atol=1e-4, rtol=1e-3`。

### 6.3 test_backend_conformance（CPU vs Vulkan）

同一构图在 CPU 与 Vulkan 上分别执行并逐元素比较，不依赖外部数据。16 组、约 84 个对照用例：逐元素/一元/归约/归一化/softmax/损失/拷贝与形状/索引/matmul（含 batch 与 tile 边界）/卷积/WeightNorm×分组卷积/池化与 2D 转置卷积/cast/归一化反向/形状扩展/大链，以及网格上限（内部设 `TRC_VK_MAX_GROUPS=64`）与 `pad` 脏数据清零。容差 `atol=1e-5, rtol=2e-4`（比黄金更严，两侧同算法）。`pool_2d_back` 仅 CPU 实现，不对照。

### 6.4 test_vulkan（冒烟）

设备注册与属性、缓冲 alloc / set / get / clear、视图 host 直读直写语义、`supports_op` 的代表性判定、空图 compute。

### 6.5 test_stress（规模压力）

在真实规模下验证“不静默算错 / 不崩”、数值有限性与训练步零分配（8 个用例）：逐元素、拷贝与 F16 往返、索引、卷积、batch matmul、训练有限性、`get_rows_back` 扫描、图级复用峰值。

档位：默认 `small`（1700 万元素）；`TRC_STRESS_SCALE=full` 追加 6400 万 / 2.5 亿等更大规模（需较大显存）。默认 CTest 只跑 small。

## 7. 死亡测试

由 `tests/expect_abort.cmake` 包装：退出码 `0` = 未中止（失败）；`77` = 跳过（通过）；其它非 0（含 Windows 异常码）= 按预期中止（通过）。可选 `EXPECT_REGEX` 校验中止消息。

| CTest 用例 | 验证的中止语义 | 需要 |
|---|---|---|
| `grad_repeat_expand_abort` | 同一图重复 `graph_build_backward_expand` | — |
| `grad_shared_param_abort` | 两张已建反向的图共享参数 | — |
| `graph_alloc_coverage_abort` | 图级分配时存在未覆盖张量 | — |
| `mul_mat_inner_abort` | `mul_mat` 内维不一致 | — |
| `mul_mat_batch2_abort` | `mul_mat` `ne2` 不整除 | — |
| `mul_mat_batch3_abort` | `mul_mat` `ne3` 不整除 | — |
| `checkpoint_dup_name_abort` | checkpoint 多优化器分区名重复 | — |
| `checkpoint_dup_tensor_abort` | checkpoint 跨分区张量名重复 | — |
| `vulkan_index_oob_abort` | 索引越界（设备端错误缓冲后中止） | Vulkan 设备 |
| `vulkan_cast_type_abort` | Vulkan `cast` 非 F32↔F16 | Vulkan 设备 |
| `vulkan_storage_range_abort` | descriptor range 超 `maxStorageBufferRange` | Vulkan + `TRC_VK_MAX_STORAGE_RANGE=4096` |
| `vulkan_device_lost_abort` | `VK_ERROR_DEVICE_LOST` 专用消息 | Vulkan + `TRC_VK_FORCE_SUBMIT_RESULT=-4` |
| `vulkan_submit_result_abort` | 通用提交失败消息 | Vulkan + `TRC_VK_FORCE_SUBMIT_RESULT=-13` |

说明：多数死亡测试只断言“非 0 退出”，不校验消息内容；只有后两个用 `EXPECT_REGEX` 校验 `VkResult` 文案。无 Vulkan 设备时 Vulkan 死亡测试返回 `77`（跳过）。

## 8. 黄金数据（tests/golden）

由 PyTorch 生成，随仓库提供，测试无需本机 PyTorch 即可运行。

- 形状约定：`.npy` 为 C 序，形状 = `ne` 反转 `(ne3, ne2, ne1, ne0)`；读取端拒绝 F 序。
- 清单：`cases.txt`（前向，61 条）、`grad_cases.txt`（反向，16 条）。前向清单行格式：`<name> <op> <n_attrs> <attr...> <n_inputs> <ne0>x<ne1>x<ne2>x<ne3>:<type> ...`；反向用 `case/in/param/node/loss` 的 DSL。
- 其它套件：`nn_*`（层）、`loss_*`、`optim_*` / `optim_sched_*`、`trace_*`。
- 重新生成（需 Python + numpy + torch）：

```sh
python scripts/gen_golden.py
python scripts/gen_golden.py --out tests/golden --seed 1234
```

数据缺失时，依赖它的用例打印提示并跳过（CTest 仍记为通过）。

## 9. 覆盖边界

- **默认规模有限**：压力测试默认 `small`（1700 万元素）；`full` 档（6400 万 / 2.5 亿、更大 matmul）需手动设置，默认 CTest 不覆盖。
- **“无设备”记为通过**：Vulkan 用例在无设备时早退并返回 `0`，CTest 记为 PASSED 而非 SKIPPED；无法从 CTest 结果直接区分“真验证”与“跳过”。死亡测试的跳过返回 `77`。
- **无 SDK 时候选消失**：`TRC_VULKAN=OFF` 时全部 Vulkan 用例不注册，测试矩阵缩小。
- **跨平台**：测试与工具链以 Windows / MSVC 为中心，未在其它平台/编译器上布测试。
- **与 ggml 本体的一致性不在 `ctest` 内**：由独立工具 `tools/ggml_crosscheck` 完成。
- **`pool_2d_back` 的 Vulkan**：不覆盖（仅 CPU 实现），靠 `graph_first_unsupported` 如实报告。
- **chunked 提交覆盖有限**：只有 `golden_vulkan_chunked`、`grad_golden_vulkan_chunked`、`backend_conformance_chunked` 三个变体。
- **死亡测试粒度**：多数只断言退出码。
- **框架能力**：无超时、无 fixture、无并行隔离、无覆盖率 / ASan 等；失败仅汇总。
- **已知未定义行为不测**：如 `set_rows` 重复索引。
- **黄金数据可复现性**：生成依赖 torch / numpy（版本未锁定）；数据缺失即静默跳过。
