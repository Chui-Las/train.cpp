# 核心概念与功能概览

本文档说明 traincpp 的定位、能力范围与核心对象模型，作为进一步阅读其它文档的入口。各功能的详细说明见对应专题文档。

## 1. 定位

- 通用 C++20 深度学习**训练**库，命名空间 `traincpp`。
- 核心与后端分离：核心提供张量、计算图、自动求导、网络层、损失、优化器、模型 I/O；后端提供设备与 kernel。
- 库本体不含第三方运行时依赖；Vulkan 后端为可选组件，仅依赖 Vulkan SDK。
- 训练组件（自动求导编排、优化器、学习率调度、梯度裁剪等）在主机端实现，与具体后端无关。
- 以 ggml v0.23.0 为兼容基准：数据类型取值、张量布局（`ne` / `nb`）、算子语义一致；训练产物可导出为 GGUF。
- 计算精度：计算 kernel 目前以 F32 为主；F16 在部分路径可用于存储与转换（见第 4 节）。

## 2. 能力总览

### 2.1 张量与内存

- 张量：`new_tensor_1d/2d/3d/4d`，四维布局，`ne` 最内层约定与步长 `nb` 同 ggml。
- 形状操作：视图（`view_1d..4d`）、`reshape_1d..4d`、`permute`、`transpose`、`cont`、`cast`、`dup`。
- 上下文：`context_new` 管理张量元数据（arena），可选由后端统一分配张量数据。
- 内存：整上下文分配 `buffer_alloc_ctx_tensors`；图级生命周期复用 `buffer_alloc_graph_tensors`；图中间量回收 `context_release_graph_tensors`。

### 2.2 计算图与自动求导

- 图：`graph_new`、`graph_build_forward_expand`（迭代式后序展开、去重）。
- 自动求导：反向是前向算子的组合，追加进同一计算图；一次 `graph_compute` 同时完成前向与反向。
- 参数与损失：`tensor_set_param` / `tensor_set_loss`；梯度写入持久累加器并支持梯度累积。
- 训练控制：`graph_reset`（清零梯度 + 损失播种）、`graph_reset_accumulate`（仅播种，用于 micro-batch）、`graph_get_grad`。
- 梯度裁剪：`optim_clip_grad_norm`（全局 L2）。

### 2.3 算子

- 逐元素二元：`add` / `add1` / `sub` / `mul` / `div`。
- 逐元素一元与激活：`neg` / `abs_op` / `sqr` / `sqrt_op` / `exp_op` / `log_op` / `sin_op` / `cos_op` / `clamp` / `sgn` / `step` / `relu` / `leaky_relu` / `sigmoid` / `tanh_op` / `silu` / `gelu` / `gelu_erf` / `erf_op` / `softplus` / `hardswish` / `scale` / `scale_bias`。
- 归约：`sum` / `sum_rows` / `mean`。
- 归一化：`norm` / `rms_norm` / `group_norm`，以及对应的 `*_back`。
- 注意力：`soft_max` / `soft_max_ext`（含 scale、mask、ALiBi）。
- 索引：`get_rows` / `get_rows_back` / `set_rows`。
- 形状扩展：`repeat` / `repeat_back` / `concat` / `pad` / `pad_ext`（零填充与 reflect）/ `pad_back` / `acc`。
- 卷积与池化：`im2col` / `im2col_back` / `conv_1d` / `conv_2d` / `col2im_1d` / `conv_transpose_1d` / `conv_transpose_2d` / `pool_2d` / `pool_2d_back`。
- 线代：`mul_mat`（支持 batch 维与广播）。
- 损失：`cross_entropy_loss` / `cross_entropy_loss_back`。

### 2.4 神经网络层

以 POD 结构体 + 自由函数提供，权重布局与 PyTorch `state_dict` 一致（张量 `ne` 为其形状反序）。

- `Linear` / `Embedding`
- `Conv1d`（支持分组）/ `Conv2d` / `ConvTranspose1d`
- `WeightNorm`（配合 `linear_forward_weight` / `conv1d_forward_weight` / `conv2d_forward_weight` / `convtranspose1d_forward_weight` 前向）
- `LayerNorm` / `RmsNorm` / `GroupNorm`
- `Dropout`（inverted dropout，train / eval）

初始化函数：`nn_init_constant` / `nn_init_uniform` / `nn_init_normal` / `nn_init_kaiming_uniform`，以及 `nn_fan_in` / `nn_fan_out`。层的 `*_init` 会自动把参数标记为可训练。

### 2.5 损失

- `mse_loss` / `l1_loss`：全元素均值，组合实现。
- `cross_entropy_loss`：按行均值，作用于 logits 与同形状的概率目标（one-hot / 软标签），不接收类别索引目标。

### 2.6 优化器与学习率调度

- 优化器（主机端，后端无关）：SGD、AdamW，数值语义对齐 PyTorch。
- 参数分组：`optim_add_param_group_sgd` / `optim_add_param_group_adamw`，组间超参独立。
- 其他：`optim_zero_grad`、`optim_clip_grad_norm`、`optim_get_lr` / `optim_set_lr`。
- 调度器：StepLR、ExponentialLR、CosineAnnealingLR，以及 warmup + cosine（本库扩展）。

### 2.7 随机数

`Rng`（splitmix64，确定性、跨平台一致），用于权重初始化与 Dropout；状态可随 checkpoint 保存与恢复。

### 2.8 模型 I/O

- GGUF 写出：版本 v3、32 字节对齐；支持原类型与 F32→F16；写端不量化。
- GGUF 读取：版本 v2 / v3；支持 F32/F16/BF16/F64/I8/I16/I32/I64，以及 Q4_0/Q4_1/Q5_0/Q5_1/Q8_0 反量化。
- 校验：`gguf_validate`（结构自检）。

### 2.9 训练状态

- checkpoint 复用 GGUF 容器：参数 + 优化器状态 + 优化器超参 + 每参数 step + 可选 RNG / 调度器 epoch。
- schema 恒写 v2，读取兼容 v1 / v2；支持多优化器分区（如双网络训练的 G / D）。
- 接口：`checkpoint_save` / `checkpoint_load` / `checkpoint_probe` / `checkpoint_verify`。

### 2.10 后端

- CPU 参考后端：通用步长路径，正确性优先。
- Vulkan 后端：同一份代码跨设备运行，shader 构建期编译并嵌入。
- 能力查询：`Device::supports_op` 是唯一门控；`graph_first_unsupported` 可在执行前对整图预检。
- 不支持的算子或类型组合会在执行前明确中止，不会静默跳过或错算。

## 3. 核心对象模型

### 3.1 Context

张量元数据的 arena 分配器与张量 registry。`context_new(mem_size)` 创建；`ContextParams.no_alloc` 默认 `true`，此时张量数据由后端 buffer 统一分配。`context_free` 释放上下文。

### 3.2 Tensor

- 四维形状 `ne[4]`（`ne[0]` 最内层）与字节步长 `nb[4]`；`nb[0] = type_size`。
- `tensor_set` / `tensor_get` 是**原始缓冲区字节**语义（偏移与长度以字节计）；非连续视图（`permute` / `transpose` / 带步长视图）必须先 `cont()` 物化再按元素读写。
- 视图不拥有内存，数据指向源张量，且必须把源登记为 `src[0]`。
- 标志位：`TENSOR_FLAG_PARAM`、`TENSOR_FLAG_LOSS`、`TENSOR_FLAG_OUTPUT`（图级分配下需要保留可读的中间量/视图）。

### 3.3 Graph

- 由输出节点后序展开，节点去重；`nsrc==0` 的节点记为叶子。
- 固定构建顺序：前向展开 → 反向展开 → 分配 buffer → 每步 `graph_reset` + `graph_compute`。
- 图构建完成后不可再新增张量。

### 3.4 Device / BufferType / Buffer

- `device_count` / `device_get` / `device_by_type` / `device_cpu` 枚举与选择设备。
- `Device::default_buffer_type()` 取得默认缓冲类型；`buffer_alloc_ctx_tensors` / `buffer_alloc_graph_tensors` 分配张量数据；`buffer_free` 释放。
- `Device::alloc_buffer(size)` 可自行分配缓冲。

### 3.5 参数、损失与梯度

- `tensor_set_param` 标记可训练参数（要求无输入的叶子张量）；`tensor_set_loss` 标记损失（F32 标量）。
- `graph_build_backward_expand` 自动为参数与损失创建 F32 梯度累加器（`grad_acc`）。
- 梯度以 inplace 方式累加进持久累加器；每个训练步必须 `graph_reset`，micro-batch 累积用 `graph_reset_accumulate`。

### 3.6 多图

同一上下文中，一个参数（或反向梯度路径上的中间量）只能属于一个已构建反向的图；同一计算图不可重复展开反向。双网络训练采用「冻结 / 解冻 + detach 输入」协议，使用两个 Graph 与两个优化器。

## 4. 当前边界与限制（概要）

详细清单见《功能与限制》。概要：

- 计算精度：计算以 F32 为主；F16 仅在 CPU 少量算子（`cast`、`get_rows` 表、`set_rows` 值、`im2col` 图像、`soft_max` mask）与 Vulkan `cast` 中出现；BF16/F64/I8/I16/I32/I64 主要用于存储与 `cast`；量化类型不参与计算。
- 量化：读取端支持 5 种 legacy 量化（Q4_0/Q4_1/Q5_0/Q5_1/Q8_0）反量化；不支持 K-quant / IQ 读取，写端不量化。
- 未实现：混合精度训练（AMP）、量化训练、分布式训练、梯度检查点、flash attention、融合反向 kernel、`out_prod`；`set_rows`、`col2im_1d` 的反向；设备端融合优化器算子。
- 后端差异：部分算子仅在 CPU 可用（如 `pool_2d_back`），部分算子/类型组合在 Vulkan 上范围更窄（如 `cast` 仅 F32↔F16、索引仅 I32）。用 `graph_first_unsupported` 在训练前确认。
- 平台：核心为可移植 C++20，当前验证平台为 Windows 11 + MSVC。
