# 模型导出与加载

GGUF 是 ggml 生态的模型文件格式。本库写出 v3、读取 v2/v3，允许训练产物被 ggml 生态程序直接加载，也允许读取外部 GGUF 用于热启动 / 微调。

## 1. 写出模型

```cpp
GgufWriter* w = gguf_writer_new();
gguf_writer_set_arch(w, "my.arch");                       // general.architecture
gguf_writer_set_u32(w, "my.layers", 8);                   // 任意元数据
gguf_writer_set_str(w, "my.note", "说明文本");
const int32_t dims[3] = {64, 8, 4};
gguf_writer_set_arr_i32(w, "my.dims", dims, 3);

for (Tensor* p : params.items) {
    gguf_writer_add_tensor(w, p->name, p, TYPE_F32);      // 默认 F32；可 TYPE_F16
}
gguf_writer_write(w, "model.gguf");                       // 恒写 v3、32 字节对齐
gguf_writer_free(w);

gguf_validate("model.gguf");                              // 结构自检
```

要点：

- 张量必须**连续且已分配数据**；名字非空、唯一、长度 < `MAX_NAME`（63 字符）。
- `out_type` 允许：源类型原样，或源为 F32 时转为 `TYPE_F16`；其余组合报错（写端不量化）。
- 元数据支持 13 种标量类型，以及 i32 / i64 / f32 / 字符串数组。
- 写失败返回 `false`，并删除半成品文件。

## 2. 读取与反量化

```cpp
GgufFile* f = gguf_open("model.gguf");          // 第二参数 false = 只读元数据
const char* arch = gguf_get_str(f, "general.architecture");
int64_t     n    = gguf_tensor_count(f);

// 方式一：按文件形状建张量 -> 分配 -> 载入
Tensor* w = gguf_new_tensor(ctx, f, "layer.weight", TYPE_F32);
buffer_alloc_ctx_tensors(ctx, dev->default_buffer_type());
gguf_load_tensor(f, "layer.weight", w);

// 方式二：读出为普通 F32 向量（自动反量化/转换）
std::vector<float> tmp((size_t) gguf_tensor_nelements(f, 0));
gguf_tensor_to_f32(f, "layer.weight", tmp.data(), (int64_t) tmp.size());

gguf_close(f);
```

- `gguf_load_tensor` 契约：目标为 F32 时可载入任意支持类型（自动转换 / 反量化）；否则要求类型一致（原样拷贝）。目标必须连续、元素数一致。
- `gguf_open(path, false)` 只解析元数据，适合快速探测。

## 3. 命名与布局

- 张量维度按 `ne[0..]` 顺序落盘（与 ggml 一致，不反转）；PyTorch 形状为其反序。
- 张量名由使用方指定（层参数的默认名字形如 `fc1.weight`、`fc1.bias`）。
- 视图 / 非连续张量需先 `cont()` 物化后再导出。

## 4. 支持的类型与版本

- 版本：写出恒为 v3；读取支持 v2 / v3；仅小端主机。
- 写出：8 种基本类型原样，或 F32→F16；不量化。
- 读取反量化：`F32 / F16 / BF16 / F64 / I8 / I16 / I32 / I64`，以及 `Q4_0 / Q4_1 / Q5_0 / Q5_1 / Q8_0`。
- 不支持：K-quant / IQ 等量化类型读取时明确报错，不会误读。

## 5. 校验

```cpp
gguf_validate("model.gguf");   // 重新解析并校验头/版本/KV/张量信息/对齐/offset/数据范围
```

GGUF 格式本身无校验和，`gguf_validate` 只做结构与范围校验（成功打印摘要并返回 `true`）。

## 6. 与 ggml 的互操作验证

`tools/ggml_crosscheck` 用 ggml 本体读取本库导出的文件并逐项核对，作为独立证据：

```sh
cmake -S tools/ggml_crosscheck -B build/ggml_crosscheck -G Ninja \
      -DTRC_GGML_SOURCE=<ggml 源码路径>
cmake --build build/ggml_crosscheck
build/ggml_crosscheck/bin/ggml_crosscheck
```

该工具会导出一个样例模型与一个 checkpoint，再用 ggml 读取校验。它是可选工具，不参与库的构建，也不引入运行时依赖。

## 7. 常见错误

- 打开：魔数不正确、版本不支持（仅 v2/v3）、文件访问失败。
- 解析：元数据 KV 损坏、张量 offset 不连续、张量数据越界、张量名重复。
- 载入：读取端暂不支持类型、类型不匹配（目标需 F32 或同类型）、目标不连续、元素数不匹配。
- 写出：名字重复/过长、张量不连续或数据未分配、out_type 组合不支持。
